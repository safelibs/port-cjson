## Implementation Details
1. Add `/validator/` to `.gitignore` if absent so the nested validator checkout remains an external workspace artifact.
2. Preserve this safe workspace and build context while collecting the baseline:
   - `safe/` is a two-crate Rust workspace with `crates/libcjson` and `crates/libcjson_utils`.
   - The member Cargo manifests build both `cdylib` and `staticlib` artifacts.
   - `safe/CMakeLists.txt` bridges CMake to Cargo, builds `safe-libcjson` and `safe-libcjson-utils`, and wraps Rust static archives into ABI-compatible shared libraries.
   - `safe/debian/control` declares Debian build dependencies including `cargo`, `cmake`, `debhelper-compat`, `ninja-build`, and `rustc`.
   - `scripts/build-debs.sh` must build package artifacts through `dpkg-buildpackage` rooted in `safe/`, using `scripts/lib/build-deb-common.sh`.
   - `safe/tests/CMakeLists.txt` is the source of truth for checked-in upstream-style C tests, regressions, relink checks, and fuzz-corpus compatibility tests.
3. The validator `port` mode for this repository consumes `.deb` overrides and the generated port lock. It does not need, and should not be given, a path to `safe/`; `safe/` remains the implementation and local-regression location for fixes only.
4. Clone or update the validator checkout in place. Record the actual validator commit used at runtime in `validator-report.md`; do not hard-code the prior observed validator commit `d1c08d01cd50b34a7aeb62c5630e28df0eb6cd97`.

   ```sh
   if [ -d validator/.git ]; then
     git -C validator pull --ff-only
   else
     git clone https://github.com/safelibs/validator validator
   fi
   git -C validator rev-parse HEAD
   ```

   If `validator/` has local changes, do not overwrite them. Record the dirty state in `validator-report.md` and stop for review.
5. Read validator setup and invocation details from `validator/README.md`, then run the validator static checks expected by the current validator tree:

   ```sh
   make -C validator unit
   make -C validator check-testcases
   ```

6. Run local non-packaging checks in the main checkout:

   ```sh
   bash scripts/install-build-deps.sh
   bash scripts/check-layout.sh
   python3 -m unittest tests.test_build_port_lock
   ```

7. Create an initial `validator-report.md` scaffold and commit `.gitignore` plus the scaffold before package validation. The committed SHA is the baseline `Validated port commit` and must be passed as `SAFELIBS_COMMIT_SHA`.
8. Run package and validator steps only through this validation worktree protocol:

   ```sh
   bash -lc '
   set -euo pipefail
   main_root="$PWD"
   validated_sha="$(git rev-parse HEAD)"
   validation_tree="$main_root/.work/validation-build-worktree"
   rm -rf "$main_root/dist" "$main_root/.work/validation" "$validation_tree"
   git worktree prune
   cleanup_validation_tree() {
     git worktree remove --force "$validation_tree" >/dev/null 2>&1 || rm -rf "$validation_tree"
   }
   trap cleanup_validation_tree EXIT
   git worktree add --detach "$validation_tree" "$validated_sha"
   validation_status=0
   (
     cd "$validation_tree"
     SAFELIBS_COMMIT_SHA="$validated_sha" bash scripts/build-debs.sh
     SAFELIBS_VALIDATOR_DIR="$main_root/validator" \
     SAFELIBS_RECORD_CASTS=1 \
     SAFELIBS_COMMIT_SHA="$validated_sha" \
     bash scripts/run-validation-tests.sh
   ) || validation_status=$?
   mkdir -p "$main_root/.work"
   rm -rf "$main_root/dist" "$main_root/.work/validation"
   if [ -d "$validation_tree/dist" ]; then cp -a "$validation_tree/dist" "$main_root/dist"; fi
   if [ -d "$validation_tree/.work/validation" ]; then cp -a "$validation_tree/.work/validation" "$main_root/.work/validation"; fi
   exit "$validation_status"
   '
   ```

9. Regardless of the hook exit status, parse `.work/validation/artifacts/port/results/cjson/summary.json` and every non-summary JSON file under `.work/validation/artifacts/port/results/cjson/`. Current validator `port` mode can exit 0 while recording failed port testcase results.
10. Do not fix cJSON behavior in this phase unless a setup or script failure prevents collection of testcase results.
11. After copied ignored artifacts are in place, inspect the main checkout for tracked dirt. If package validation dirtied a tracked file such as `safe/debian/changelog`, fix the validation workflow so the side effect remains in `.work/validation-build-worktree/`; do not erase the evidence with `git restore`, `git checkout --`, or destructive cleanup in the main checkout.
12. If `summary.json` records `failed: 0`, run proof verification for the cjson subset and record the result:

   ```sh
   python3 validator/tools/verify_proof_artifacts.py \
     --config validator/repositories.yml \
     --tests-root validator/tests \
     --artifact-root .work/validation/artifacts \
     --proof-output .work/validation/artifacts/proof/cjson-port-validation-proof.json \
     --mode port \
     --library cjson \
     --min-source-cases 5 \
     --min-usage-cases 246 \

     --min-cases 253 \
     --require-casts
   ```

13. Write `validator-report.md` with validator URL and commit, validated port commit, report commit if different, canonical packages (`libcjson1`, `libcjson-dev`), built deb filenames and lock metadata, cjson checks by kind, baseline failures, artifact paths, next failure class, and an explicit note that validator sources were not modified.
